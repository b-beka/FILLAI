# Runbook: поддержка FILL AI

Все команды бэкенда запускаются из папки `backend` (в Windows: `venv/Scripts/python`).

## Запуск

```bash
# бэкенд
cd backend
venv/Scripts/python -m uvicorn app.main:app --reload --port 8000

# фронтенд
cd frontend
npm run dev
```

Проверка: `GET http://localhost:8000/health`. Ответ `healthy` значит, что база отвечает.
`degraded` и `"db": false` — база недоступна (см. «Supabase на паузе»).
`"ai_ready": false` — не задан ключ ИИ-провайдера (см. «Замена ключа»).

## Копия и восстановление базы

Копия всей базы в один файл (gzip + JSON):

```bash
python -m scripts.backup_db
```

Файл появится в `backend/backups/` (папка в `.gitignore`). В нём данные пользователей:
не коммитьте его и не отправляйте в чаты. Делайте копию перед миграциями и перед показом.

Восстановление работает только в пустую базу (таблицы созданы миграциями, строк нет),
существующие данные не затираются. Сферы, которые засевают миграции, не мешают: если
курсов и подтем нет, скрипт сам заменит их сферами из копии:

```bash
python -m scripts.restore_db backups/<файл>.json.gz --yes
```

Если в базе есть другие данные (курсы, пользователи, подтемы), скрипт остановится с сообщением и ничего не изменит. Загрузка идёт
одной транзакцией: при ошибке в базе не останется половины данных. Скрипт работает с базой
из `DATABASE_URL` в `backend/.env`, проверьте, куда он указывает, прежде чем запускать.

## Supabase на паузе

Бесплатные проекты Supabase останавливаются после нескольких дней без активности.
Признаки: `/health` отвечает `degraded`, вход и генерация падают с ошибкой подключения к базе.

1. Откройте проект в панели Supabase.
2. Нажмите «Restore project» (или «Resume») и подождите несколько минут.
3. Проверьте `/health`: должно быть `"db": true`. Перезапускать бэкенд обычно не нужно,
   соединения восстановятся сами.

Чтобы проект не засыпал перед показом, откройте любую страницу приложения за день до него.

## Кончился лимит OpenRouter (ответ 429)

Когда провайдер отвечает 429, генерация курса возвращает `success: false` и сообщение
«Достигнут лимит запросов к ИИ-провайдеру». Остальное приложение работает.

1. Подождите несколько минут (если это лимит по частоте запросов).
2. Если исчерпан баланс или дневной лимит бесплатной модели, пополните баланс в кабинете
   OpenRouter или смените модель (`OPENAI_MODEL` в `backend/.env`).
3. После правки `.env` перезапустите бэкенд.

Дневной лимит бесплатных моделей OpenRouter: 50 запросов в сутки. Один курс тратит
14-26 запросов, то есть в день получается 2-3 курса. Если лимит исчерпан, пользователь
увидит «Дневной лимит бесплатной модели исчерпан, попробуйте завтра». Не тратьте пробные
запуски в день показа. Пополнение кабинета OpenRouter на $10 поднимает лимит до 1000
запросов в сутки.

## Замена ключа

1. Выпустите новый ключ в кабинете провайдера, старый отзовите.
2. Впишите его в `backend/.env` (`OPENAI_API_KEY`), файл нельзя коммитить и пересылать.
3. Перезапустите бэкенд. `uvicorn --reload` следит только за `.py`-файлами и не заметит
   изменения `.env`, поэтому остановите процесс (Ctrl+C) и запустите заново.
4. Проверьте `/health`: `"ai_ready": true`.

## Новый аккаунт для показа

```bash
python -m scripts.create_user --username Demo --email demo@fill.ai --name "Демо"
```

Пароль спросят в терминале (не короче 8 символов). Письмо подтверждения не нужно.
Лимит генераций у обычного аккаунта 100 курсов; роль `admin` снимает этот лимит.
